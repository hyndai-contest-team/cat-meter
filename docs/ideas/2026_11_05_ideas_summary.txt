고양 미터기 아이디어 취합
작성일: 2026년 11월 5일

1. 취합 대상과 문서 성격

- 2026_11_01_cat_meter.txt: 고양이로 차량 상태를 표현하는 드라이브 경험
- 2026_11_01_leejihun_nyang_meter.txt: 가상 단위 '냥'을 사용하는 요금 미터와 냥풀
- 2026_11_01_joonhyuk_cat_meter_cost_split.txt: 탑승 구간별 실제 차량 비용 분담

이 문서는 세 제안의 중복을 묶고 차이와 결정할 사항을 정리한 취합본이다. 모든 기능을 개발하기로 합의한 최종 기획서는 아니다. 원본은 유지한다.
SDK, 정책, 법령, 경쟁 서비스 관련 내용은 원문에 적힌 조사 결과와 주장이다. 이번 취합에서 외부 자료를 다시 검증하지 않았으며, 구현 완료나 현재 사용 가능 여부를 보증하지 않는다.

2. 세 가지 기획 방향

가. 고양이 기반 차량 정보 시각화
- 대상: 친구들과 함께 차를 타는 사람
- 목적: 함께 이동하는 시간을 재미있게 만들기
- 핵심: 속도에 따라 고양이가 달리고, 조향·정차·공조 상태에 반응한다.
- 출발 전 꾸미기 → 이동 중 반응 → 도착 후 기념 영수증으로 이어진다.
- 차량 속도에 연동되는 달리기 모션을 핵심 매력으로 유지한다는 방향이 기존 대화에서 제시됐다.

나. 냥미터기
- 대상: 친구·동승자와 이동을 재미있는 요금 미터로 경험하려는 사람
- 목적: 택시 미터기 형식으로 이동 거리와 시간을 '몇 냥'으로 표현하기
- 핵심: 기본·거리·저속 시간 요금과 심야 할증을 가상 단위로 표시한다.
- 도착 후 냥수증, 인원별 요금 분할, 음성 안내로 확장한다.
- 실제 결제와 가상 냥 표시는 분리해야 한다. 명칭을 냥으로 바꾸는 것만으로 실제 금전 거래의 법적 성격이 달라진다고 판단하지 않는다.

다. 탑승 구간별 실제 비용 분담
- 대상: 친구·가족과 함께 이동하거나 차량을 공동 사용하는 사람
- 목적: 중간 승하차를 반영하여 유류비·충전비·통행료를 나누기
- 핵심: 사람별 탑승 구간과 차량 거리를 연결해 부담액을 계산한다.
- 좌석별 이름 지정 → 구간 기록 → 비용 계산 → 휴대폰 정산 공유로 이어진다.
- 공동 사용 차량의 월별 사용량 리포트를 반복 사용 시나리오로 제안한다.

3. 공통으로 묶이는 기능

가. 차량 데이터 기반 이동 기록
- 속도, 이동 거리와 시간으로 운행 상태 및 기록을 구성한다.
- 비용 분담 방향에서는 좌석별 점유와 연비·전비 정보를 추가로 사용한다.
- 이동 시작·종료 기준, 차량 트립 초기화 기준, 중간 하차 처리 기준을 정해야 한다.

나. 내비게이션 옆 분할 화면
- 기존 조사 문서는 Pleos Connect의 두 앱 동시 표시를 공통 근거로 사용한다.
- 작은 창에는 핵심 정보, 넓은 창에는 상세 내역을 표시한다.
- 시각화 방향은 고양이와 차량 상태, 냥미터 방향은 현재 냥 숫자가 중심이다.
- 실제 비용 분담 방향은 주행 중 화면보다 백그라운드 기록을 우선한다.

다. 도착 후 영수증
- 시각화 방향: 오늘의 고양이, 이동 거리·시간을 담는 기념 이미지
- 냥미터 방향: 기본·거리·시간 냥과 합계를 보여주는 냥수증
- 실제 비용 분담 방향: 사람별 탑승 구간, 추정 비용, 부담액을 보여주는 정산 카드
- 저장·공유는 공통 기능으로 묶을 수 있다. 다만 영수증의 주목적은 선택한 기획 방향에 따라 달라진다.

라. 고양이와 동승자 설정
- 출발 전 고양이 이름·외형·소품을 선택하고 저장한다.
- 비용 분담을 선택하면 탑승자 이름 및 좌석 지정이 추가된다.
- 운전자 조작 없이 이동 중 기록과 표현이 이어지는 흐름을 지향한다.
- 동승자 휴대폰 연동은 확장 후보이며 구현 경로는 미확인이다.

4. 방향별 추가 기능

가. 차량 정보 시각화
- 조향각에 따라 고양이와 소품이 기울어지는 표현
- 공조 풍량에 따라 수염·털이 흔들리는 표현
- 밤과 날씨에 따른 배경 변화
- 정차 때 시작한 놀이를 다음 정차에서 이어가는 행동
- 주행 횟수에 따라 쿠션·스크래처 등이 늘어나는 고양이 공간
- 빠른 속도나 거친 운전이 특별한 보상 조건이 되지 않는 구성

나. 냥미터기
- 가상 기본요금, 거리요금, 저속 시간요금, 심야 할증
- 운전자·동승자가 정한 단가 또는 고정 금액의 분할
- 현재 냥 음성 안내
- Gleo에 특정 탑승자의 하차를 요청하면 해당 냥수증 표시
- 목적지 예상 냥, 과속 시 미터 정지, 모은 냥으로 꾸미기는 추가 후보
- 대화 내용을 STT·LLM으로 처리하는 요금 합의 도우미는 별도 AI 후보
- 실제 결제는 공모전에서 모의 구현하는 방안 제안

다. 실제 비용 분담
- 좌석별 탑승자 지정과 점유 변화에 따른 구간 경계 기록
- 좌석 변경과 오감지는 이후 주차 상태에서 확인·수정
- 구간 거리 ÷ 평균 연비·전비 × 단가로 비용 추정
- 구간 비용을 해당 구간 탑승자 수로 나누어 사람별 합산
- 운전자 포함·제외 옵션
- 통행료 통과 시점의 탑승자에게 비용 분배
- 실제 영수증 금액을 이용한 비례 보정
- QR로 휴대폰 웹에서 내역 확인 및 개인 송금 링크 연결
- 주·월별 사용량과 비용 리포트
- 서버가 필요한 후보: 정산 공유, 외부 유가 API, 공휴일 정보

비용 계산 예시
- 4명이 130km를 함께 타고, 1명이 내린 뒤 나머지 3명이 120km를 이동한 경우
- 앞 구간 비용은 4명, 뒤 구간 비용은 3명에게 나눈다.
- 먼저 내린 사람은 앞 구간만 부담한다. 실제 금액 계산에서는 반올림 잔액 처리도 정해야 한다.

5. 합의가 필요한 차이

가. 앱의 주목적
- 즐거운 드라이브 경험, 가상 요금 놀이, 실제 비용 분담은 각각 해결하려는 문제가 다르다.
- 모두 한 번에 포함하면 화면과 사용 흐름이 복잡해질 수 있다.
- 차량 데이터·이동 기록·영수증은 공유할 수 있지만, 앱의 첫 화면과 핵심 시연은 한 방향을 먼저 정해야 한다.

나. 주행 중 고양이 표현
- 차량 정보 시각화 문서: 달리기 모션을 유지하고 구체적인 시안으로 허용 범위를 확인한다.
- 냥미터 문서: 주행 중에는 숫자만 바꾸고 장식 애니메이션을 사용하지 않는다.
- 실제 비용 분담 문서: 주행 중 정지 이미지를 사용하고, 애니메이션은 정차·충전 중 제공한다.
- 이는 서로 다른 설계안이다. '주행 중 달리기 모션을 빼기로 합의했다'고 취합하지 않는다.
- 사용자와의 기존 논의에서는 달리기 모션을 핵심으로 유지했다. 새로운 팀 합의는 별도로 필요하다.

다. 냥과 실제 원화 비용
- 택시형 기본·거리·시간 요금은 실제 유류비·충전비 계산과 다르다.
- 가상 냥, 합의한 요금, 실제 추정 경비를 같은 금액처럼 표시하지 않는다.
- 냥을 사용할 경우 원화 환산·현금 가치·꾸미기 재화 사용 여부를 정해야 한다.

라. 결제·송금 방식
- 냥미터 문서: QR 모의 결제, 실제 서비스에서는 PG 협업 검토
- 실제 비용 분담 문서: 차량 내 결제 없이 휴대폰 웹에서 개인 송금 링크 사용
- 결제 통합과 정산 내역 공유는 서로 다른 범위다. 초기 구현 범위를 정해야 한다.

마. AI와 대화 기능
- 기존 사용자 논의에서는 대화 주제 추천과 '오늘의 한마디'를 제외했다.
- 요금 합의 도우미는 다른 목적의 신규 제안으로, 채택된 기능은 아니다.
- 요금 계산 기준, AI 필요성, 대화 수집 동의 및 제공 SDK를 확인한 뒤 판단한다.

6. 검증할 항목

가. 주행 중 사용 정책
- 기존 조사에는 반복 모션을 피하라는 가이드와 DO·CarUxRestrictions 적용 요구가 정리돼 있다.
- 차량 정보 시각화 문서는 달리기 모션의 허용 여부를 미확정으로 두고 있다.
- 다른 문서의 정지 이미지 설계나 카테고리 제한 해석을 달리기 모션의 불허 확정 근거로 취급하지 않는다.
- 실제 모션 시안의 허용 범위, 앱 카테고리, 주행 중 백그라운드 기록 조건을 확인한다.
- 비용 분담 문서의 한국 주행 제한 해제 조건, 성능 수치, 에뮬레이터 속도 설정 관련 주장은 추가 대조가 필요하다.
- 신호 대기·일시 정지와 플랫폼상 주차 상태는 동일하다고 가정하지 않는다.

나. SDK와 데이터
- 기존 시각화 문서에 조사된 경로: AAOS 속도, Pleos 조향각·공조·거리·시간·와이퍼 API
- 추가 제안의 확인 대상: 좌석별 점유, 뒷좌석 센서 제공 여부, 연비·전비, 통행료, 경유지 도착 이벤트, Gleo 호출 및 음성 기능
- 좌석 점유는 사람의 신원을 뜻하지 않으므로 이름 지정과 확인이 필요하다.
- 실제 연비·전비와 순간 전비를 구분하고, 구간 비용 계산에 적합한 데이터를 선택한다.
- 와이퍼 작동으로 실제 강우를 확정하거나, 조향각으로 차체 기울기를 직접 측정했다고 표현하지 않는다.
- 원문에 타 출품작에서 가져왔다고 적힌 API·권한명은 공식 SDK와 대조한다.
- API 목록 확인과 에뮬레이터·실차 수신 검증을 구분한다.

다. 비용 분담과 법적 해석
- 두 비용 관련 문서는 여객자동차 운수사업법 제81조와 출퇴근 예외를 검토 대상으로 적었다.
- 냥미터 문서는 경비 분담을 폭넓게 제한하는 해석을 적었고, 실제 비용 분담 문서는 공동 사용 차량·친구 여행·출퇴근을 구분했다. 따라서 두 문서의 법적 판단이 완전히 같지는 않다.
- 친구 여행 경비 분담과 공동 사용 차량 유지비 분담에 대한 적용 여부는 확정하지 않는다.
- '미터 시작 시각' 또는 '허용 시간에 해당하는 구간' 중 어느 기준을 사용할지도 제안이 다르다. 어느 기준도 법적으로 충분하다고 취합하지 않는다.
- 모의 결제, 개인 송금 링크, 가상 냥이라는 구현 방식만으로 법적 문제가 해소된다고 판단하지 않는다.
- 이번 취합은 법률 검토를 새로 수행한 것이 아니다.

라. 차별화와 사업성
- 기존 문서의 경쟁 저장소 검색 결과는 2026년 11월 1일 작성자의 조사 기록이다. 현재 경쟁 기능 부재를 증명하는 결론으로 사용하지 않는다.
- 달리는 캐릭터, 차량 상태 기반 육성, 운행 기록 등 유사 요소가 원문에 보고돼 있다.
- 실제 비용 분담 방향에서는 고양이가 핵심 기능에 어떤 역할을 하는지 보완해야 한다.
- 제휴·유료 리포트·플랫폼택시·자율주행 확대는 사업성 후보이며 확정 계획이 아니다.
- MAU, 개발 기간, 구현 난도는 검증된 수치가 없다.

7. 다음 회의 결정 목록

1) 핵심 방향: 차량 정보 시각화 / 냥미터 / 실제 비용 분담 중 무엇을 우선할지
2) 주행 화면: 달리기 모션 유지안과 숫자·정지 이미지안의 정책 확인 방법
3) 영수증: 기념 이미지 / 가상 요금 / 실제 경비 중 우선 제공할 내용
4) 탑승자 입력: 이름만 지정할지, 좌석 점유 센서까지 연결할지
5) 결제 범위: 공유만 / 모의 결제 / 송금 링크 중 선택
6) 첫 검증: 속도·조향각 수신과 분할 화면, 좌석 점유 제공 여부

8. 취합 결과

공통 기반은 '차량 데이터로 함께 이동한 과정을 기록하고, 고양이와 영수증으로 보여준다'는 것이다.
핵심 차이는 이동을 재미있게 표현할지, 가상 요금을 보여줄지, 실제 비용을 나눌지에 있다.
세 방향의 기능을 모두 확정하기보다, 위 결정 목록을 바탕으로 핵심 경험과 첫 구현 범위를 정한다.

상세 근거와 참고 링크는 1항의 각 원문에서 확인한다.

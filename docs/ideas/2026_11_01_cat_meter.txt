고양 미터기 추가 기능 아이디어
작성일: 2026년 11월 1일
기반: 2026년 10월 31일 아이디어 회의 및 후속 논의

1. 기획 방향

- 주요 타겟은 친구와 함께 차를 타는 사람이다.
- 목적은 친구들과 차를 타는 시간을 더 재미있게 만드는 것이다.
- 앱의 중심은 차량의 속도, 조향각, 정차 상태, 공조 정보를 고양이의 행동으로 표현하는 '차량 정보 시각화'이다.
- 특히 차량 속도에 따라 고양이가 달리는 모션을 핵심 매력으로 유지한다. 정책 확인 전에 이 기능을 삭제하거나 정적인 화면으로 대체하지 않는다.
- 주행 속도에 따라 고양이의 모습이 달라지는 기존 아이디어를 확장하여, 실제 차량의 움직임과 환경에 반응하는 고양이를 표현한다.
- 친구들이 출발 전에 고양이를 함께 꾸미고, 이동 중에는 반응을 구경하며, 도착 후에는 기록을 남기는 흐름으로 구성한다.
- 핵심 경험은 '우리 차 안에 친구들과 함께 키우는 고양이가 타고 있다'는 느낌이다.
- 아래 내용은 기능 제안이다. 공식 문서에서 데이터 접근 경로와 멀티윈도우 지원을 확인했으나, 에뮬레이터·실차에서 데이터 수신이나 주행 중 화면 동작을 검증한 것은 아니다.

2. 기본 기능

가. 오늘의 고양이 꾸미기
- 출발 전에 친구들과 고양이 이름, 털 색, 의상, 소품을 선택한다.
- 함께 타는 친구들끼리 고른 고양이를 저장하고 다음 드라이브에서 다시 불러올 수 있도록 한다.
- 복잡한 캐릭터 설정보다는 짧은 시간 안에 함께 고르는 재미에 집중한다.

나. 주행 상황에 따른 고양이 행동
- 신호 대기 등 정차 중: 식빵을 굽거나 앞발을 핥는다.
- 천천히 이동할 때: 주변을 두리번거리며 산책한다.
- 일정하게 주행할 때: 여유롭게 뛰며 배경을 구경한다.
- 고양이는 화면의 일정한 위치에서 달리기 동작을 반복하고, 차량 속도에 따라 동작의 빠르기가 달라지는 형태를 우선 구상한다.
- 정체 상황: 쿠션 위에 드러눕거나 휴식을 취한다.
- 목적지 도착: 짐을 풀고 생선을 먹는 등 도착 동작을 보여준다.
- 속도가 높아야 좋은 장면을 볼 수 있는 구조 대신, 느리게 이동하거나 멈춰 있어도 다양한 볼거리를 제공한다.

다. 동승자의 집사 역할
- 동승자가 고양이에게 모자, 선글라스, 쿠션, 장난감 등을 골라준다.
- 선택한 소품은 이후 고양이의 행동에도 계속 반영한다.
- 예시: 친구가 준 쿠션 위에서 정차 중 잠들고, 씌워준 모자는 회전할 때 살짝 기운다.
- 꾸미기는 차량 정보를 표현하는 캐릭터의 외형 설정으로 구성한다. 주행 중 운전자 조작을 요구하지 않는다.
- 초기에는 출발 전 설정으로 제공하고, 동승자 휴대폰 연동은 구현 가능성을 확인한 뒤 확장한다.

라. 도착 후 고양 영수증
- 오늘 꾸민 고양이와 실제 이동 시간, 이동 거리를 기념 이미지로 남긴다.
- 이미지를 저장하여 친구들과 공유할 수 있도록 한다.
- 대화 문구를 만들어 넣기보다, 함께 탄 날의 고양이 모습을 남기는 기념사진에 가깝게 구성한다.

3. 차량 특화 기능

가. 회전에 반응하는 고양이
- 좌회전 시 고양이가 오른쪽으로 살짝 기울어지는 등 차량의 움직임에 반응한다.
- 굽은 길에서는 앞발로 쿠션을 붙잡는 모습을 보여준다.
- 의상과 소품도 함께 움직이도록 하여 실제 차에 타고 있는 느낌을 강화한다.

나. 차창 밖 환경 반영
- 밤에는 고양이 공간에도 달이 뜨고, 비가 오면 창문에 빗방울이 맺힌다.
- 실제 드라이브 환경과 고양이 공간이 이어지는 느낌을 만든다.
- 시간대, 날씨 등 필요한 정보의 제공 방식과 정확도는 확인이 필요하다.

다. 공조에 반응하는 고양이
- 에어컨을 켜면 바람에 수염이 흔들린다.
- 히터를 켜면 따뜻한 자리에서 졸거나 몸을 편다.
- 공식 HVAC API 목록에서 에어컨 상태, 풍량, 설정 온도, 현재 온도의 조회·구독 경로를 확인했다. 실제 데이터 수신과 난방 상태 판단 기준은 추가 검증한다.

라. 정차할 때 이어지는 행동
- 정차하면 장난감을 꺼내 놀고, 출발하면 장난감을 챙긴다.
- 다음 정차에서는 앞서 하던 놀이를 이어간다.
- 상태마다 같은 애니메이션만 반복하기보다 행동이 이어지도록 하여 살아 있는 느낌을 만든다.
- 차량이 멈춘 사실만으로 신호 대기, 정체, 주차를 구분할 수 있다고 가정하지 않는다. 필요한 데이터와 구분 방법을 확인한다.

마. 우리 차에 자리 잡는 고양이
- 함께 주행한 횟수가 쌓이면 쿠션, 스크래처 등 고양이 공간의 소품이 늘어난다.
- 친구들과 다시 탔을 때 이전과 달라진 고양이 공간을 발견하는 재미를 제공한다.
- 빠른 속도나 거친 운전이 성장 조건 또는 보상이 되지 않도록 한다.

4. 사용 흐름 예시

출발 전
- 친구들과 저장된 고양이를 불러오거나 새 고양이를 고른다.
- 이름과 소품을 정한다.

이동 중
- 내비게이션과 고양 미터기를 분할 화면으로 함께 표시하는 구성을 목표로 한다.
- 고양이가 주행, 회전, 정차에 반응한다.
- 동승자가 준 소품이 행동에 반영된다.
- 정차 중 시작한 행동은 다음 정차에서 이어진다.
- 밤이나 비 등 현재 환경이 고양이 공간에도 반영된다.

도착 후
- 도착 동작을 보여준다.
- 오늘의 고양이와 이동 기록이 담긴 고양 영수증을 저장한다.

5. 우선 구현 제안

1순위: 핵심 경험
- 고양이 이름 및 소품 선택
- 차량 속도에 연동되는 달리기 모션 및 정차 반응
- 내비게이션 옆 작은 창에서도 보이는 화면 구성
- 회전에 따른 고양이 반응
- 도착 후 고양 영수증

2순위: 반응의 연속성과 몰입감
- 소품과 차량 반응의 연결
- 정차할 때 이어지는 행동
- 밤과 비 등 환경 반영

확장 검토
- 공조 상태 연동
- 주행 횟수에 따른 고양이 공간 변화
- 동승자 휴대폰 연동

6. Pleos 차량 데이터 연동 조사 결과

조사 기준
- 2026년 11월 1일 확인한 Pleos 및 Android 공식 문서를 기준으로 정리했다.
- API 목록에 존재하는 것과 현재 프로젝트·차량에서 실제로 사용할 수 있는 것은 구분한다.
- 일부 API 상세 페이지에서는 함수 본문이 표시되지 않아 인자, 반환값, 갱신 주기, 개별 권한까지 확인하지 못했다.

가. 속도와 정차
- Pleos 공식 FAQ는 계기판과 같은 속도 데이터 소스를 사용하려면 AAOS CarPropertyManager로 PERF_VEHICLE_SPEED를 읽도록 안내한다.
- Android 문서상 속도 단위는 m/s이며 Car.PERMISSION_SPEED 권한이 필요하다.
- 속도로 이동과 정지를 판별할 수 있지만, 신호 대기·정체·주차·목적지 도착을 속도만으로 확정할 수는 없다.

나. 조향각
- SteeringWheel API 목록에 getCurrentSteeringWheelAngle, registerSteeringWheelAngle, checkSteeringWheelAngleCapabilities가 있다.
- 핸들 각도를 고양이와 소품의 기울어짐 표현에 활용하는 방안을 검토한다.
- 조향각은 실제 차체 기울기나 횡가속도와 동일하지 않다. 방향 부호, 범위, 갱신 주기 및 속도와의 조합은 검증해야 한다.

다. 공조
- HVAC API 목록에 에어컨 상태, 풍량, 전원, 설정 온도 및 현재 온도의 조회·구독 API가 있다.
- 차량 설정을 변경하지 않고 상태를 읽어 고양이의 반응에 활용한다.
- 에어컨 켜짐이나 설정 온도만으로 실제 냉방·난방 상태를 단정하지 않는다.

라. 이동 거리와 시간
- Odometer API 목록에 getTripCurrentDrivingDistance, getTripCurrentDrivingTime 및 관련 구독 API가 있다.
- 차량 트립의 시작·초기화 기준과 앱이 기록하려는 드라이브 구간을 맞추는 방법을 확인한다.

마. 날씨와 시간대
- Wiper API 목록에 getCurrentWiperState, registerWiperState가 있다.
- 와이퍼 작동과 연결된 연출은 가능성을 검토할 수 있으나, 와이퍼 작동을 실제 강우로 확정하지 않는다.
- 밤 배경은 기기 시간 기반으로 구현할 수 있다. 실제 날씨를 표현하려면 별도 정보 경로가 필요하다.

바. 접근 조건
- 공식 SDK 접근 안내는 Vehicle State를 별도 신청 없이 사용 가능한 상태로 안내한다. Vehicle Control은 준비 중으로 표시되어 있다.
- 현재 기획은 상태 조회를 중심으로 하므로 차량 제어 API를 전제로 하지 않는다.
- API별 권한과 check...Capabilities를 통한 지원 여부 확인이 필요하다. 실제 프로젝트의 SDK 제공 상태도 확인한다.

7. 내비게이션과 동시 표시

- Pleos Connect는 고정된 차량 정보 영역인 Driving view와 별도로 최대 두 앱을 함께 표시하는 멀티윈도우를 지원한다.
- 공식 Window Policy 기준 Connect-S는 두 앱을 1:1로, Connect-W는 2:1 또는 1:2로 배치한다.
- 따라서 내비게이션 한쪽, 고양 미터기 다른 쪽의 배치는 플랫폼이 지원하는 구성이다. 모든 차종에서 동일한 크기·동작을 보장한다는 의미는 아니다.
- 한 창을 사용하는 portrait 화면과 확장된 landscape 화면을 고려하고, 창 크기·위치 변경에 대응한다.
- 내비게이션을 별도로 구현하거나 앱 안에 포함하는 기능은 이번 기획의 전제가 아니다.
- 동시 표시 지원과 주행 중 우리 앱의 사용 허용 여부는 별개이다.

8. 주행 중 달리기 모션의 정책 검토

확인된 정책
- DO(Distraction Optimization) 선언이 없는 앱은 기본 정책상 주행 중 사용할 수 없다.
- DO를 선언한 앱도 CarUxRestrictions와 ActiveRestrictions에 따라 기능별 제한을 적용해야 한다. DO 선언만으로 심사 통과나 주행 중 사용이 보장되지는 않는다.
- 공식 안전 설계 가이드는 운전자의 주의를 과도하게 끄는 애니메이션을 최소화하거나 제한하고, 장식적이거나 반복해서 움직이는 시각 요소를 피하도록 안내한다.
- 게임·영상·브라우저 기능을 가진 앱에는 별도의 주행 중 사용 제한이 있다.

현재 판단과 미확정 사항
- 확인한 문서에는 '속도에 따라 달리는 모션이 있으면 무조건 주행 중 사용 금지'라는 개별 규정은 없다.
- 다만 지속적으로 반복되는 달리기 모션은 위 가이드와 충돌할 여지가 있다.
- 차량 정보 시각화라는 기획 목적만으로 허용이 확정되는 것도 아니며, 현재 문서만으로 불허 가능성이 높다고 단정할 근거도 없다.
- 고양 미터기의 실제 화면과 모션이 주행 중 허용되는지는 아직 확인되지 않았다.
- 달리기 모션은 핵심 기능으로 유지하고, 구체적인 시안을 기준으로 허용 범위를 확인한다. 현재 단계에서 정적인 화면으로 대체하기로 결정한 것은 아니다.

9. 구현 전 확인 사항 및 설계 원칙

- 에뮬레이터에서 속도, 조향각, 풍량 데이터의 조회·구독을 우선 검증한다.
- 필요한 데이터의 접근 권한, 갱신 주기, 사용 제약을 확인한 뒤 기능 범위를 확정한다.
- 차량 데이터로 확인한 상태와 시간대·외부 날씨 정보 등으로 표현한 환경을 구분한다.
- 이동 시간과 거리의 측정 기준, 주행 시작·종료 및 도착 판단 방법을 정한다.
- 운전 중 운전자의 조작을 요구하지 않고, 움직임과 효과는 운전에 방해되지 않는 수준으로 표현한다.
- 급가속, 급회전, 높은 속도로 특별한 장면이나 보상을 얻는 구조는 사용하지 않는다.
